# Writing guidance

Write ordered steps with checkable completion criteria and keep reference material beside the concept it qualifies. Put every-path requirements in the main procedure; disclose branch-only material behind precise context pointers stating when to read it.

Minimize always-loaded context while preserving human agency. Each pointer must identify its target and real trigger branches. Prefer established leading words over repeated sentences. Keep meaning in one source of truth; the environment is authoritative for commands/configuration, so avoid cached duplicates.

Prune stale or irrelevant instructions and no-ops. Phrase target behavior positively; reserve prohibitions for hard guardrails and pair them with the desired action. Split by branch or sequence only when the context boundary earns its navigation cost. Follow repository authority before generic skill packaging/invocation conventions.
