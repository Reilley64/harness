# Glossary format

Use a context heading, a short context description, then Language. Each entry is a bold canonical term, a colon and one or two sentences defining what it is. List rejected synonyms under _Avoid_. Group natural clusters with subheadings.

Include context-specific concepts, not generic programming vocabulary. Choose one canonical term per meaning. For multiple contexts, the glossary map links each context's glossary and records their relationships. Repository conventions override this default shape.
