# Environment retrospective

Read the assigned run history, primary logs, artifacts and existing build/check/CI guidance. Use supplement/writing-for-agents when proposing instruction changes.

Inspect navigation, hidden dependencies, missing/unwired checks, standards judgment gaps, overly broad steering, tool economy and information access. Mechanical problems belong in deterministic checks rather than more prose where feasible. Prefer fixing an existing broken guardrail to inventing a duplicate.

Propose severity-ordered candidates with evidence and expected benefit. Follow repository rules about when implementers read standards; avoid generic manual-host assumptions. Return the report without recursive team-building, unrequested provisioning, changes to personal/global guidance or self-authorized improvements.
